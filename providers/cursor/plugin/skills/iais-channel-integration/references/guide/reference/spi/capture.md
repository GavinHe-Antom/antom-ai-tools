# capture — Capture an authorized payment

## Contract and platform availability

- Interface: `com.alipay.iacqintegrationhub.channel.sdk.spi.payment.PaymentService`
- Signature: `CaptureResponse capture(CaptureRequest request)`
- Java requirement: Optional; the SDK throws UnsupportedOperationException unless overridden.
- Platform capability: `ChannelSpiOperation.CAPTURE`
- Platform endpoint: `POST /{channelCode}/channel/capture`; requires channel-module registration and an SPI bean.
- Institution route key: `capture` (DomainControlConfig.pathMap)

Capture an authorized payment.

This captures an authorized transaction; it is not the initial pay call. Non-card capture is outside the product scope. Map synchronous capture results and asynchronous notifyCapture results separately.

## Usage constraints

- The institution protocol determines support for full, partial, and multiple captures. Confirm amount limits and idempotency rules during integration.
- captureId is required in synchronous capture responses but optional in capture notifications. Apply the rules for each method separately.

API definition: alipay.ais.payments.capture. See [Payment field definitions](../payment-sources.md)
and [Machine-readable field notes](../payment-field-notes.json).

## Implementation and verification

The CLI connects the template through `spi/ChannelPaymentService.capture`; implement validate, mapRequestBody, mapUrlParameters and mapResponse in that method's anonymous `ChannelApiExtension`. No per-method Mapping helper class is generated. The dynamic URL API is used by default. Return an empty Map when the path has no placeholders.

Implement the generated validate hook using the field rules on this page and the confirmed institution protocol. Do not infer required fields from other methods.

Test real field mapping, missing fields, exceptions that must not become success, institution failure/unknown states, empty responses, and boundary values. For operations that make HTTP calls, also cover non-2xx responses.
