# notifyReceivePayment — Received payment notification

[SPI index](README.md) · [Integration guide](../../README.md)

## Contract and platform availability

- Interface: `com.alipay.iacqintegrationhub.channel.sdk.spi.notify.NotificationService`
- Signature: `PaymentNotifyRequest notifyReceivePayment(BaseChannelRequest request)`
- Java requirement: Optional; the SDK throws UnsupportedOperationException unless overridden.
- Platform capability: `ChannelSpiOperation.RECEIVE_PAYMENT_NOTIFY`
- Platform endpoint: SDK contract only; no connected platform HTTP endpoint.
- Institution route key: This SPI does not select an institution destination route.

Notify the result of an offline received payment. Only the SPI contract exists; there is no corresponding iPay API or exposed platform endpoint.

SDK contract only. There is no external platform endpoint or complete iPay flow. Do not reuse a card notification path as a substitute.

## Implementation and verification

The CLI does not generate this method. Confirm the platform endpoint and invocation path first; implementing an Adapter method alone does not connect the capability.

Do not deliver it as a connected capability until the platform flow is available.

Test real field mapping, missing fields, exceptions that must not become success, verification failure preventing forwarding, notification correlation IDs, and ACK behavior. For operations making HTTP calls, also cover non-2xx responses.
