# pay — Initiate payment / initial 3DS

[SPI index](README.md) · [Integration guide](../../README.md)

## Contract and platform availability

- Interface: `com.alipay.iacqintegrationhub.channel.sdk.spi.payment.PaymentService`
- Signature: `PayResponse pay(PayRequest request)`
- Java requirement: An abstract method that must be implemented when providing this interface.
- Platform capability: `ChannelSpiOperation.PAY`
- Platform endpoint: `POST /{channelCode}/channel/pay`; requires channel-module registration and an SPI bean.
- Institution route key: `pay` (DomainControlConfig.pathMap)

Process payment/authorization in one-call 3DS, or the initial 3DS authentication in two-call 3DS. The Adapter
maps standard fields to the institution message and maps the institution response back to the standard payment result.

One-call mode completes the institution payment/authorization here; two-call mode completes its first stage here. Do not treat both flows as final success solely because of the method name. PayRequest has no
extendInfo; map amount and redirection information to fields that actually exist.

## Usage constraints

- For one-call 3DS, pay completes payment or authorization. For two-call 3DS, pay completes stage one and authenticateAuthorize completes the second authorization call.

API definition: alipay.ais.payments.pay. See [Payment field definitions](../payment-sources.md)
and [Machine-readable field notes](../payment-field-notes.json).

## Implementation and verification

The CLI connects the template through `spi/ChannelPaymentService.pay`; implement validate, mapRequestBody, mapUrlParameters and mapResponse in that method's anonymous `ChannelApiExtension`. No per-method Mapping helper class is generated. The dynamic URL API is used by default. Return an empty Map when the path has no placeholders.

Implement the generated validate hook using the field rules on this page and the confirmed institution protocol. Do not infer required fields from other methods.

Test real field mapping, missing fields, exceptions that must not become success, institution failure/unknown states, empty responses, and boundary values. For operations that make HTTP calls, also cover non-2xx responses.
See [Mapping rules](../../04-mapping-and-results.md); [Security](../../05-security.md); [Notifications](../../07-notifications-and-callbacks.md).
