# notifyPayment — Payment result notification

[SPI index](README.md) · [Integration guide](../../README.md)

## Contract and platform availability

- Interface: `com.alipay.iacqintegrationhub.channel.sdk.spi.notify.NotificationService`
- Signature: `PaymentNotifyRequest notifyPayment(BaseChannelRequest request)`
- Java requirement: An abstract method that must be implemented when providing this interface.
- Platform capability: `ChannelSpiOperation.PAYMENT_NOTIFY`
- Platform endpoint: `POST /{channelCode}/channel/notifyPayment/{merchantId}`; requires channel-module registration and an SPI bean.
- Institution route key: This SPI does not select an institution destination route.

Notify the payment result only when the transaction reaches a final state.

SDK comments define this as a final-state payment notification. Verify/decrypt before mapping result, payment correlation IDs, and amount. The return value is a standard notification request, not the institution ACK.

## Usage constraints

- BaseChannelRequest carries the original institution message and headers. PaymentNotifyRequest is the mapped standard payment notification, which the platform forwards to iPay.
- Payment, capture, and refund notifications use separate SPI methods. Map each according to its result semantics.
- The platform handles ACK using the actual iPay response. responseText belongs to NotifyResponse, not the notification SPI output, and is not guaranteed to be the literal success.

API definition: alipay.ais.payments.notifyPayment. See [Payment field definitions](../payment-sources.md)
and [Machine-readable field notes](../payment-field-notes.json).

## Implementation and verification

The CLI connects executeNotification through `spi/ChannelNotificationService.notifyPayment`. Implement validate and map in that method's anonymous `ChannelNotificationExtension`, plus enabled verification/decryption hooks in the security customization layer. No per-method Mapping helper class is generated.

Verify the signature before mapping. Confirm that the institution ACK requirements are compatible with the platform endpoint.

Test real field mapping, missing fields, exceptions that must not become success, verification failure preventing forwarding, notification correlation IDs, and ACK behavior. For operations making HTTP calls, also cover non-2xx responses.
See [Mapping rules](../../04-mapping-and-results.md); [Security](../../05-security.md); [Notifications](../../07-notifications-and-callbacks.md).
